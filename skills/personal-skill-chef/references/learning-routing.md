# Learning Routing

Use this only after a substantial task exposes a reusable lesson.

## Quality gate

Persist a lesson only when all three are credible:

- **Signal:** supported by observed behavior, a user correction, or reproducible evidence.
- **Frequency:** likely to recur, not a one-off detail.
- **Impact:** retaining it will materially improve correctness, speed, or user experience.

If the lesson is uncertain, keep it in the current answer rather than turning it into a permanent rule.

## Route to the narrowest durable home

1. **Project structure or code** when the system itself can make the correct behavior obvious or enforceable.
2. **Deterministic script or test** when repeated mechanics or validation can be automated reliably.
3. **Owning Skill** when the lesson changes domain-specific decisions or workflow.
4. **Global routing instruction** only when it genuinely applies across projects and Skills.
5. **Backlog suggestion** when useful but not yet authorized or sufficiently proven.

Prefer updating an existing owner over creating a duplicate rule. Prune stale or redundant instructions when revising an owner. Any persistent edit still requires the authorization normally needed for that target.
