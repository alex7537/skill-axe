# ZeroTier + Windows App：画面刷新但鼠标键盘失效

## 2026-09-14 事件结论

用户最终确认远端鼠标、键盘恢复。记录为“功能恢复，根因未定”，不能写成已经修复 Obsidian、GNOME 或 xrdp 的已知缺陷。

已验证：
- Mac 的 ZeroTier 服务 ONLINE、网络成员状态 OK，目标路由经过 ZeroTier 接口；所见节点路径为 DIRECT。
- 目标四次 ping 零丢包，平均约 5.1 ms；SSH 端口和两套 RDP 端口响应，RDP 协商正常。这是当时的小样本，不排除间歇问题。
- Windows App 当前连接使用 xrdp 独立桌面；另一份连接配置属于另一套 RDP 入口，不能混同服务、凭据或会话。
- 故障时 GNOME 时钟继续变化。前台 Obsidian 曾显示窗口菜单，Escape 后菜单关闭；用户随后仍报告鼠标键盘失效。
- 完整退出 Windows App、重启并重连后未立即恢复；未删除缓存、保存凭据或修改永久证书信任。
- 最新重连记录 → chansrv 显示编号 → GNOME DISPLAY → cgroup 的关联，定位到了一个持续数天的 X11 桌面。事件中为 :14 / c26；这些仅为历史值，不能直接用于未来操作。
- 该 GNOME 环境缺少 XDG_SESSION_ID。Xorg 日志记录了重连、尺寸变化和 Num Lock 同步；相关进程当时为 S/Sl 等状态，并非 T、Z 或 D，但这不证明其响应正常。
- 没有执行会话注销、GNOME/Xorg 重启、Obsidian 终止或永久配置修改。用户在后续只读输入采样建议之后报告恢复，但没有提供采样结果或确认执行细节。

未证实：Obsidian 占用输入、GNOME 输入阻塞、xrdp 输入路径异常、焦点/修饰键异常中的任何一个具体根因。缺失 XDG_SESSION_ID 是遗留线索，不是因果证明。恢复也不能归功于只读检查命令。

## 复用时的决策顺序

1. 恢复原配置：只读核对 Windows App 的目标、端口、用户名和网关；不读取密码。区分 TCP 可达、RDP 协商成功、认证成功和桌面可操作四个层级。
2. 网络检查通过后，停止反复重启 ZeroTier。确认实际服务是 xrdp 还是 GNOME Remote Desktop，再检查对应日志。
3. 观察症状：画面/时钟是否刷新；鼠标移动、点击和键盘是否分别响应；是否只有一个应用异常。Escape 关闭菜单只证明那次输入有效，不代表完整恢复。
4. 重新查询会话和进程；用本次重连时间匹配 xrdp-chansrv.<display>.log，再以 DISPLAY 和 /proc/<PID>/cgroup 确认目标。旧日志文件不证明旧会话仍存活；不能通过最后一个 PID、最大会话号或单个 LockedHint 猜测目标。
5. 有 SSH 权限后，先读 loginctl、进程状态、目标 Xorg 日志、GNOME 环境中与会话有关的少量字段。不要打印整个 environ，其中可能含凭据。
6. 若故障仍在，可在核对 DISPLAY 和 XAUTHORITY 后短时间运行 xinput test-xi2 --root。让用户只移动鼠标、点标题栏、按 Shift，避免录入真实文本。该测试在本事件中仅被提出，未取得结果；不能描述为已验证的修复。不要把输出通过 head 截断而丢掉后续关键事件，也不要将采样超时退出自动判定为失败。
7. 根据事件是否到达 Xorg，继续区分客户端/传输/输入设备和桌面/应用处理。若只有某个应用失效，先尝试其正常退出；任何可能丢失未保存工作的终止操作，需要明确说明目标和影响并取得相应授权。

## 容易误判的证据

- sound_process_training 的 round trip time 属于声音通道训练记录，不能直接当作鼠标键盘或完整桌面延迟。
- 历史剪贴板 MIME 错误、DPMS 缺失、快捷键覆盖、autoRepeat off，单独不足以解释鼠标键盘同时失效。
- 图形会话正常绘制不保证输入正常；进程未处于僵尸状态也不保证应用响应。
- 完整重启客户端后仍有症状，仅降低纯客户端残留状态的可能性，不能彻底排除客户端。
- 用户在自己的终端完成密码 SSH 登录，不会自动授权或共享给代理的独立 SSH 连接。先核实是否真有可复用连接；若工具不能访问该终端，明确让用户执行一组聚焦的只读命令并提供输出，不反复承诺接管。
- AX 树可能只暴露远程窗口，不能以“无变化”断言远端卡死。结合截图和用户反馈；界面焦点改变后重新定位。不要反复发送无法确认被远端接收的快捷键。

## 验收和复发处理

最低验收是用户确认鼠标点击及键盘正常；更强验收包括切换应用、实际文字输入和重连后仍可用。本事件只有用户恢复确认，未完成后续耐久验证。

复发时优先留存上述输入事件和当前会话映射，再比较 Escape、切换应用、正常关闭 Obsidian 的结果。只有反复出现明确的触发/解除关系或直接诊断证据，才能将责任归到 Obsidian。没有复发证据时保持现有配置，避免为了一个假设批量杀会话、重装软件或关闭锁屏。
