# 测评2.0：初态配对验收

实现位于项目工作区的 `a2d-layout-replay/eval_v2/`，使用前解析实际 checkout 路径并检查文件是否存在；skill 本身不携带或启动 runner。测试数据写入独立批次。当前为实验版本，局部验收通过不等于整个基准完善。

## 已确认与待验证

- PsiLab ILEnv.reset收到了seed/options却未传父类。v2通过显式runtime.install修复，仅影响新进程。
- Scene.reset前段只写位姿，但随机化后段会写完整root state。不能据此前段断言当前随机目标存在速度继承。
- v2速度选项在原生reset完成、物理预热之前，给刚体写回配置默认速度，保留随机位姿；默认速度不一定为零。不改变机器人控制器或成功判据。

## 验证顺序

1. 保护正在运行的历史测评，不热更新其依赖。先进行离线契约测试。
2. 运行legacy、seed_only、seed_velocity三组reset探针。相同seed重复前注入已知物体速度，核对实际初态、速度和双相机首帧。前两组隔离seed因素，后两组隔离速度因素。
3. 区分写回后即时速度、落定后残余速度与位姿差分；初态速度不能凭非零读数判为历史残留。
4. 同进程reset通过后，再验证跨进程与动作后reset。现有探针不等于完成这两项。
5. 使用原生随机分布采集布局，保存物体/机器人根状态、关节状态、控制目标、资产及相机配置、首帧。恢复后按冻结容差核对。不依据模型成功率筛布局。
6. 状态恢复、传感器一致性、模型执行、抓取成功分开验收；通过正控及少量模型测试后再提出100布局基准。

## 报告边界

沿用layout-pose-v3位置5mm/姿态0.02rad/关节0.01rad，仅作为临时工程容差；图像MAE和速度全部保留，不以放宽阈值掩盖问题。任何失败保留证据并阻止扩容。每日随机测评结果不与v2合并。相同seed不证明实际初态配对，恢复相同可观测状态也不保证PhysX轨迹完全确定。

## 2026-09-24小规模证据
保存原生落定状态，原样恢复速度/控制目标后检查0/1/10/60步：3布局、同进程及跨进程共48位姿检查点通过，最大位置误差0.904mm。不要与48个独立布局混淆；不代表速度、视觉、动作后恢复和模型闭环全部通过。见本机eval_v2/README.md最新报告。后续沿用这条恢复路线，不重复600步落定，不静默修改参考速度或放宽阈值。

## 运行监督与已知边界（2026-09-29）

- 同步执行使用服务端整数物理步计数核对：本动作开始计数等于上一动作结束计数，差值等于冻结步数。不要用微秒级浮点时间戳相减代替计数验收。本次实验为120Hz物理、每动作4步，区别于历史异步RPC路线。
- 恢复一致性不代表初态合法：保存并检查目标是否在预期支撑面/区域，不能凭稳定或同seed判定可抓取。现有z≥0.4m仅为具体场景的粗略门槛，不应推广为通用标准。难抓但合法的布局不得按模型成败过滤。
- 有效回合、不同布局数、配对完整覆盖分别统计；循环100布局补测不产生新的独立布局。正常抓取失败计入有效回合；基础设施错误和未执行占位不计作抓取失败。
- 先核对GPU空闲与进程归属；显存不足等待资源，不反复加载模型生成无效回合。守卫阈值是可配置预算，不等于实测最低显存。不要终止其他任务。
- 接口监听不代表恢复健康；启动后验证观测、reset、初态验收与首轮动作。监督器存活但有效计数不增长应标为阻塞，保留服务退出原因，限制相同故障的重试；避免无限换场景空转。
- 使用明确的绝对路径或配置解析启动依赖；复制到嵌套批次后重新验证路径，不能假定OUT.parent仍指向原始结果根目录。
- 新监督器必须实际启动并核对PID、首轮进展和恢复路径；脚本已写好不等于已接管。完成/中断后核对OB报告、静态快照、远端发布状态及提交，不以本地导出代替上传成功。

阶段证据：2.0三个混合模型的9次瓶子小测全部完成并抓起；后续正式测试未达全量目标，发生显存不足和reset连接关闭。详细结果由项目批次和OB拥有，不在skill中维护实时成功率。
