# 初态恢复验收：layout-pose-v3

适用于右手 A2D 抓取的布局恢复；2026-09-20 用户授权放宽初始化验收。与抓取成功判据分开，旧报告不重标。

> 版本边界：下述600步预热及清零运动描述2026-09-20的历史流程。新的落定状态恢复路线见 [a2d-eval-v2](../../a2d-eval-v2/SKILL.md)：原样恢复保存的速度和控制目标，不额外重复600步预热；保留相同的位姿工程容差。不要将两个流程混用。

## 冻结参数

| 项目 | v3 | 旧 v2 |
|---|---|---|
| 统一预热 / 稳定窗口 | 600 / 60 物理步 | 相同 |
| 根位置漂移及恢复误差（欧氏距离） | ≤5 mm | ≤2 mm |
| 根姿态差 | ≤0.02 rad | 相同 |
| 关节位置差 | ≤0.01 rad | 相同 |
| 有限线速度、角速度、关节速度超0.02 | 告警，保留数值 | 硬拒绝 |
| 非有限数据、资产身份/形状不一致、无效四元数 | 拒绝 | 相同 |

5 mm 是本项目暂定工程容差，未经任务敏感性标定，不是开源公认标准。后续修改另建版本，不根据模型成功率调整。

## 执行与解释

1. 参考生成与每次测试必须使用相同 reset 路径和布局 scene_seed；随后恢复同一布局和控制目标，清零初始运动，所有模型使用相同预热步数；与同样预热后的参考状态比较。
2. 分别记录窗口稳定性、恢复误差、观测刷新一致性。稳定不代表布局配对精确。
3. 速度异常保留告警；同时核对真实位置/姿态变化、物理时间、缓存刷新和重复写状态。放宽判据不等于修复速度来源问题。
4. 左臂单独速度超限不阻断右手任务；仍保留全身位置检查，防止碰撞、遮挡。当前实现没有删除左臂位置检查。
5. 保留 strict_passed 和原始误差。新配置用新目录；历史不改写、不与旧批次直接合并。
6. 离线重算只证明新规则的结果，正式宣称可配对前仍需同进程/跨进程恢复、图像和资产身份核对。不能仅凭验收通过声称模型测试已完成。

实现位于本机 a2d-layout-replay/protocol_v3.py；v2 保留。运行入口必须显式导入 v3 并记录代码哈希，旧 runner 不会自动切换。
抓取成功仍沿用接触＋5 cm抬升＋连续5次采样，H和动作上限不受此标准影响。

## 开源依据与边界

- [RoboDojo layout_manager.py](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/main/env/scene_manager/layout_manager.py)：检查物体位姿，300步、末100步窗口；默认每轴4cm，相对起点30°、窗口10°，不作为本项目精确配对容差。
- [LIBERO env_wrapper.py](https://github.com/Lifelong-Robot-Learning/LIBERO/blob/master/libero/libero/envs/env_wrapper.py)：恢复 MuJoCo 状态并刷新观测。
- [LIBERO evaluate.py](https://github.com/Lifelong-Robot-Learning/LIBERO/blob/master/libero/lifelong/evaluate.py)：恢复后5步零动作，再推理；该入口没有逐关节近零速度验收。

来源于2026-09-20查阅的实现；上游分支可变。借鉴统一恢复/预热流程，不能据此声称 Isaac 与 MuJoCo 的求解器内部状态可完整恢复。

## 小规模通过后的推进边界

- 恢复验收通过、模型动作执行成功、抓取任务成功分别报告；不能因18项恢复通过就宣称完整benchmark已完善。
- 先作小规模新旧初始化对照。若实际布局不同，只作端到端诊断，不作单因素因果结论。
- 扩大前冻结布局生成分布和布局ID，不按模型结果筛选；每场景100布局是后续规模，不是当前完成状态。
- 保存相机/光照配置及资产身份；缺乏视觉恢复、递归资产哈希或固定物理节奏时明确披露。
- 初始化、预热、推理和执行耗时分别计量；不能由整回合时间推断开销来源。
